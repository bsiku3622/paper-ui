# A11y

A11y Primitive는 보조 기술과 키보드 사용자를 위한 1차 바탕입니다. 포커스를 가두고 되돌리는 범위, 화면에서 숨기되 읽히는 콘텐츠, 자식을 다른 자리로 옮기면서도 열린 자리의 모드를 잇는 Portal, 상태 변화를 읽어 주는 LiveRegion입니다. 모두 자기 기하(geometry)를 갖지 않습니다. 그룹 하나에 Tab 정지 하나를 두는 탐색은 [Focus](focus.md)가, 입력과 그 설명 · 오류의 연결은 [Field](field.md)가 맡습니다.

| 컴포넌트 | Hook | 책임 | 기본값 |
| --- | --- | --- | --- |
| FocusScope | useFocusRing · useFocusWithin | contain / restoreFocus / autoFocus | 각 기능 opt-in. 범위의 초기 포커스 · 유지 · 복귀 |
| VisuallyHidden | — | as, focusable, disabled, children, ref | span. 접근성 트리에 남기며 focusable은 skip link용 |
| Portal | — | container, opener, children | document.body. display: contents 루트 하나가 열린 자리의 테마와 방향을 겁니다 |
| LiveRegion | — (함수 announce · clearAnnouncements) | politeness, atomic, children, ref | polite(status) / atomic. 처음부터 마운트해 두는 알림 영역 |

## Focus와 숨긴 콘텐츠

[contract:primitives.focus-scope.options]: #
FocusScope(`FocusScopeProps`: contain · restoreFocus · autoFocus · children)는 세 옵션을 독립적으로 선택합니다. Contain은 기본으로 켜지지 않습니다. Scope가 해제되면 restoreFocus가 원래 요소로 포커스를 돌려줍니다. 유저가 명시적으로 연 화면에서 초기 포커스를 선택하는 예시는 다음과 같습니다.

```tsx
<FocusScope contain restoreFocus autoFocus>
  <Field aria-label="첫 입력" />
  <Button onClick={close}>닫기</Button>
</FocusScope>
```

[contract:primitives.focus-ring.states]: #
useFocusRing은 focusProps·isFocused·isFocusVisible을 반환하고, focusProps에는 data-focused · data-focus-visible이 들어 있습니다. within 옵션으로 자식의 포커스도 포함하고, textInput 옵션은 텍스트 입력이라 어떤 focus에서도 링을 보이게 합니다. useFocusWithin은 focusWithinProps·isFocusWithin과 focus 진입·이탈·변경 callback(`FocusWithinOptions`)을 제공하고, focusWithinProps에는 data-focus-within이 들어 있습니다.

[contract:primitives.visually-hidden.accessible]: #
VisuallyHidden은 콘텐츠를 시각적으로 숨기고 접근성 트리에 유지합니다. as 기본값은 span이며 ref를 그 요소로 전달하고, focusable을 켜면 내부 포커스가 들어올 때 보이게 합니다. `disabled`는 region으로 투영됩니다 — button 같은 native 태그는 비활성이 되고, 그 밖의 태그는 `data-disabled`만 답니다([공통 계약](README.md#공통-계약)). Icon button의 이름과 skip link에 사용하는 예시입니다.

```tsx
<Pressable>
  <Icon><path d="M12 4v16M4 12h16" /></Icon>
  <VisuallyHidden>새 항목 추가</VisuallyHidden>
</Pressable>

<VisuallyHidden focusable>
  <a href="#main-content">본문으로 건너뛰기</a>
</VisuallyHidden>
```

동작 예제는 Playground의 Primitives 목록에서 확인합니다. 입력·포커스 계약은 단위 테스트와 실제 브라우저의 pointer·keyboard 경로로 검증합니다.

## Portal

[contract:primitives.portal.root]: #
Portal은 자식을 container(기본은 `document.body`)로 옮기고, 그 자리에 root 하나를 둡니다. root는 `display: contents`라 자기 상자가 없고, 열린 자리의 테마(`usePortalScope`)를 속성으로 다시 걸어 옮겨진 내용이 열린 자리의 모드로 그려지게 합니다. 패키지의 모든 portal이 이 길을 지나므로 [Floating](float.md)의 panel과 backdrop은 테마 속성을 직접 쓰지 않습니다. React context는 portal을 건너가지만, 바깥 [FormField](field.md)는 Portal 너머의 입력을 자기 입력으로 삼지 않습니다.

[contract:primitives.portal.carry]: #
같은 root가 열린 자리의 원본 덮어쓰기도 옮깁니다. `opener`(열린 자리의 Element를 돌려주는 함수, 주지 않으면 그때 포커스가 있는 요소)와 container를 비교해 Shape · Layout · Typography 원본 변수 가운데 값이 다른 것만 root에 얹으므로, 첫 화면부터 옮겨진 내용이 열린 자리의 크기로 그려집니다. 옮기는 일은 열릴 때 한 번 정해지고 색 역할은 옮기지 않습니다 — 모드는 위의 테마 속성이 옮깁니다. `container`는 DOM을 붙일 자리만 정합니다. [Floating](float.md)은 Trigger를 `opener`로 주고, 처음부터 열려 있는 panel은 Trigger가 commit된 다음에 열어 그 값을 읽습니다.

[contract:primitives.portal.direction]: #
같은 root가 열린 자리의 방향도 옮깁니다. `opener`의 방향이 container와 다르면 그 방향을 root의 `dir`에 쓰므로, 오른쪽에서 왼쪽으로 쓰는 하위 트리에서 연 내용의 글자와 방향키가 그 자리를 따릅니다. 방향이 같으면 `dir`을 쓰지 않아 root는 페이지의 방향을 그대로 따라갑니다. 이 값도 열릴 때 한 번 정해집니다.

```tsx
<Portal container={dialogHost}>
  <Surface fill="raised" border radius="md" padding="md">옮겨진 내용</Surface>
</Portal>
```

## 상태 변화 알리기

[contract:primitives.live-region.element]: #
LiveRegion은 보조 기술이 지켜보는 영역입니다. LiveRegion(`LiveRegionProps`: politeness · atomic · children · native div props)은 forwardRef div이고, 내용이 바뀌면 보조 기술이 읽습니다.

[contract:primitives.live-region.roles]: #
`politeness`는 `polite`(기본)와 `assertive`이고, 각각 `role="status"` · `aria-live="polite"`와 `role="alert"` · `aria-live="assertive"`로 그려집니다. `atomic`의 기본값은 `true`라 영역의 일부만 바뀌어도 전체를 다시 읽습니다. role · aria-live · aria-atomic은 LiveRegion이 정하므로 호출자가 덮을 수 없습니다.

LiveRegion은 처음부터 마운트해 두고 내용만 바꿉니다. 내용과 함께 새로 삽입되는 live region은 보조 기술이 읽지 않을 수 있습니다.

```tsx
<LiveRegion>{saved ? "저장했습니다." : null}</LiveRegion>
```

[contract:primitives.live-region.announce]: #
한 번 알리고 사라지는 메시지는 `announce(message, { politeness?, timeout? })`로 보냅니다. 화면에 요소를 남기지 않고 문서가 가진 알림 영역으로 읽히며, `timeout`(밀리초)은 메시지가 머무는 시간입니다. `clearAnnouncements(politeness?)`는 아직 읽히지 않은 메시지를 지우고, 이름을 주지 않으면 polite와 assertive 모두 지웁니다. 입력은 React Aria의 live announcer에 위임하고 Paper의 이름과 타입만 드러냅니다(`LivePoliteness` · `AnnounceOptions`).

토스트, 로딩의 시작과 끝, 폼 오류 요약이 이 두 길을 씁니다. 지켜볼 요소가 화면에 있으면 LiveRegion을, 없으면 `announce()`를 고릅니다.
