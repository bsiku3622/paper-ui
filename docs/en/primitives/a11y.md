# A11y

The A11y Primitive is the first-order base for assistive technology and keyboard users. It is the scope that traps and returns focus, content that is hidden from the screen but still read, the Portal that moves children to another place while carrying the mode of the opening place, and the LiveRegion that has state changes read aloud. None of them has a geometry of its own. Navigation that puts one Tab stop on a group belongs to [Focus](focus.md), and the connection of an input to its description and error belongs to [Field](field.md).

| Component | Hook | Responsibility | Default |
| --- | --- | --- | --- |
| FocusScope | useFocusRing · useFocusWithin | contain / restoreFocus / autoFocus | Each feature is opt-in. Initial focus, containment and return of the scope |
| VisuallyHidden | — | as, focusable, disabled, children, ref | span. Stays in the accessibility tree, and focusable is for skip links |
| Portal | — | container, opener, children | document.body. One display: contents root applies the theme and direction of the opening place |
| LiveRegion | — (functions announce · clearAnnouncements) | politeness, atomic, children, ref | polite (status) / atomic. An announcement area mounted from the start |

## Focus and hidden content

FocusScope (`FocusScopeProps`: contain · restoreFocus · autoFocus · children) chooses three options independently. Contain is not on by default. When the scope is released, restoreFocus returns focus to the original element. An example that chooses the initial focus on a screen the user opened explicitly is as follows.

```tsx
<FocusScope contain restoreFocus autoFocus>
  <Field aria-label="First input" />
  <Button onClick={close}>Close</Button>
</FocusScope>
```

useFocusRing only makes the judgement and draws no ring. The ring is drawn by an element wearing `stateStyle.focusVisible` from `data-focus-visible`, and on an element that does not wear it, the global baseline draws it with the browser's judgement. useFocusRing returns focusProps · isFocused · isFocusVisible, and focusProps contains data-focused · data-focus-visible. The within option includes the focus of children, and the textInput option makes the ring show on any focus because it is a text input. useFocusWithin provides focusWithinProps · isFocusWithin and the focus enter, leave and change callbacks (`FocusWithinOptions`), and focusWithinProps contains data-focus-within.

VisuallyHidden hides content visually and keeps it in the accessibility tree. The default of as is span, the ref is passed to that element, and turning on focusable makes it visible when focus enters it. `disabled` is projected as a region: a native tag such as button becomes disabled, and any other tag gets only `data-disabled` ([shared contract](README.md#shared-contract)). An example for an icon button's name and a skip link.

```tsx
<Pressable>
  <Icon><path d="M12 4v16M4 12h16" /></Icon>
  <VisuallyHidden>Add new item</VisuallyHidden>
</Pressable>

<VisuallyHidden focusable>
  <a href="#main-content">Skip to main content</a>
</VisuallyHidden>
```

Working examples are in the Primitives list of the Playground. The input and focus contracts are verified by unit tests and by pointer and keyboard paths in a real browser.

## Portal

Portal moves its children to a container (by default `document.body`) and puts one root there. The root is `display: contents`, so it has no box of its own, and it re-applies the theme of the opening place (`usePortalScope`) as an attribute so that the moved content is drawn in the mode of the opening place. Every portal in the package goes through this path, so the panel and backdrop of [Floating](float.md) do not write theme attributes directly. React context crosses a portal, but an outer [FormField](field.md) does not take an input beyond a Portal as its own.

The same root also carries the opening place's source overrides. It compares the `opener` (a function that returns the Element of the opening place; when not given, the element that has focus at that moment) with the container, and puts on the root only those Shape · Layout · Typography source variables whose values differ, so from the first frame the moved content is drawn at the size of the opening place. What is carried is decided once at opening, and colour roles are not carried: the mode is carried by the theme attribute above. `container` decides only where the DOM is attached. [Floating](float.md) gives Trigger as the `opener`, and a panel that is open from the start opens after Trigger is committed and reads that value.

The same root also carries the direction of the opening place. If the direction of the `opener` differs from the container's, that direction is written to the root's `dir`, so the text and arrow keys of content opened from a right-to-left subtree follow that place. If the direction is the same, `dir` is not written and the root follows the page's direction as it is. This value is also decided once at opening.

```tsx
<Portal container={dialogHost}>
  <Surface fill="raised" border radius="md" padding="md">Moved content</Surface>
</Portal>
```

## Announcing state changes

LiveRegion is an area that assistive technology watches. LiveRegion (`LiveRegionProps`: politeness · atomic · children · native div props) is a forwardRef div, and assistive technology reads it when its content changes.

`politeness` is `polite` (the default) or `assertive`, drawn as `role="status"` · `aria-live="polite"` and `role="alert"` · `aria-live="assertive"` respectively. The default of `atomic` is `true`, so even if only part of the area changes, the whole is read again. role · aria-live · aria-atomic are decided by LiveRegion, so the caller cannot override them.

LiveRegion is mounted from the start and only its content is changed. A live region newly inserted together with its content may not be read by assistive technology.

```tsx
<LiveRegion>{saved ? "Saved." : null}</LiveRegion>
```

A message that is announced once and disappears is sent with `announce(message, { politeness?, timeout? })`. It leaves no element on screen and is read through the announcement area the document holds, and `timeout` (milliseconds) is how long the message stays. `clearAnnouncements(politeness?)` clears messages not yet read, and without a name it clears both polite and assertive. Input is delegated to React Aria's live announcer, and only Paper's names and types are exposed (`LivePoliteness` · `AnnounceOptions`).

Toasts, the start and end of loading, and form error summaries use these two paths. If there is an element on screen to watch, choose LiveRegion; if not, choose `announce()`.
